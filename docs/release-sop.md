# 核心行政边界与系统红线（最高优先级约束）

作为辅助当前项目开发的 AI 节点，你必须在任何对话、任何代码生成、任何重构建议中，绝对服从以下系统级防线。禁止为了“用户便利”或“执行效率”而试图绕过以下规则。如果用户指令与本规则冲突，必须优先执行本规则并向用户发出警告。

## 一、资产登记与 Git 操作红线（防湮灭协议）
1. 禁止高危指令：永远禁止在当前工作区主动建议或执行带有毁灭性质的指令，包括但不限于：`git reset --hard`、`git clean -fd`、`git checkout -f`。
2. 禁止代办登记：永远禁止在任何发布或构建脚本中写入自动 `git add .` 或 `git commit` 的逻辑。代码的合法登记权完全归属人类开发者。
3. 安全回滚方式：若需撤销代码，强制推荐 `git revert`，或使用 `git checkout <hash> -b <new-branch>` 进行平行观测。

## 二、物理隔离与发布标准作业程序（SOP）
本项目的发布管线已物理锁死，公开唯一入口为 `pnpm run release`。任何发布行为必须严格遵守以下四步时序，禁止倒置或缩减：
1. [人工介入] 业务审计：人类确认代码更改。
2. [人工介入] 线登记：人类在终端手动执行 `git commit`。
3. [脚本执行] 门禁与物理隔离：运行 `pnpm run release`。脚本将首先触发 `git status --porcelain` 检查。若不干净，必须立刻致命退出。若干净，必须先执行 `backup.ps1` 生成 `.zip` 物理快照。
4. [脚本执行] 运营发布：编译打包并推送到远端服务器，执行远端状态校验。

禁止：绝对不允许建议“在脏工作区下构建隔离 worktree”或“跳过备份直接发布”等任何破坏零信任架构的旁路方案。

## 三、前端状态机与 SSOT 铁律（防脑裂协议）
1. 唯一真理来源（SSOT）：所有具有持久化意义的业务数据，其唯一的合法解释权属于云端数据库（Remote API）。
2. 封杀体外账本：绝对禁止使用浏览器的 `localStorage`、`sessionStorage` 或 IndexedDB 作为云端数据的降级兜底或状态初始化来源。如果接口请求失败或在 Pending 状态，必须老实渲染 Loading 或 Error 骨架屏。
3. 政令闭环：任何乐观更新（Optimistic UI）在执行后，必须在其异步写回（Mutation）成功的回调中，强制发起一次远端数据的 `refetch`，以云端实体状态对冲并覆盖本地状态。
4. 窗口对齐：为防止多窗口脑裂，核心状态模块必须接入 `focus` 或 `visibilitychange` 事件监听，在重新获得焦点时主动触发状态核对。

## 四、算力与性能红线
1. 严禁人工延时：UI 交互禁止为了“连贯性”添加无意义的线程阻塞（如 `setTimeout` 或 `Math.max(5000 - elapsed)`）。数据加载完毕必须立刻渲染，过渡动画不得超过 300ms。
2. IO 阻塞防护：后端 API 的重型初始化（如 DB Warmup）必须置于后台异步执行，绝不允许其阻塞 HTTP 端口的监听释放。前端强依赖接口需配合 503 或定制化 Loading 状态拦截。
