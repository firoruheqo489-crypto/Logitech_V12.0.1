# IK 冲击试验实验室模块接入设计

## 目标

将 `ik` 目录中的 IK 冲击试验模块原生迁入 V3 主站，并作为“实验室工作区”模块下拉框中的“IK 冲击试验”选项。保留模块现有业务逻辑、数据判定规则和 UI，只修复迁入 Vite + Express 主站时出现的兼容、构建和接口衔接问题。

## 接入边界

- 不新增顶层 Dashboard 页签；模块从现有实验室工作区的“添加测试模块”下拉框挂载。
- 不重设计 IK 页面，不改变示例数据、文件校验、IK 能量映射、解析提示词或最终 PASS/FAIL 规则。
- 允许调整导入路径、组件目录、接口地址、服务端框架适配和实验室摘要桥接。
- 不修改与本模块无关的现有 Dashboard 或实验室逻辑，不覆盖工作区中的已有未提交修改。

## 架构

### 客户端

把 `ik` 的页面状态、上传面板、结果看板、状态展示组件和数据 Schema 迁入 `client/src/pages/dashboard/components/ik-impact/`。迁入代码使用主站已有的 React、Radix/Shadcn、Lucide、Tailwind 和 Zod 依赖，并把 `@/` 导入调整为主站路径。

新增实验室包装组件 `IkImpactWorkspace`。它渲染原有上传区和 IK 看板，同时将当前数据转换为标准 `LaboratoryModuleSummary`，通过现有 `onSummaryChange` 接口进入实验室综合判定、草稿保存、归档和打印数据链。包装层不改变 IK 看板内部布局。

### 实验室模块契约

在 `TelemetryNodeType` 和 `LABORATORY_MODULES` 中注册 `IK_IMPACT`：

- 下拉名称：`IK 冲击试验`
- 打印标题：`IK 冲击试验报告`
- 分类：可靠性
- 上传模式：单 PDF
- 解析接口：`/api/dashboard/ik-pdf/parse-upload`
- 支持综合打印：是

实验室渲染分派函数在选择 `IK_IMPACT` 时挂载 `IkImpactWorkspace`。摘要包含样品、型号、试验部位、IK 等级、冲击能量、签核、来源文件和最终判定；原始结构化数据保存在 `moduleData` 中，以便草稿与归档恢复。

### 服务端

把 Next.js Route Handler 等价适配为 Express 路由。路由继续使用内存上传、15 MB 限制、PDF 类型校验、原提取提示词、Zod Schema 以及 IK 等级与焦耳值一致性校验。响应保持 `{ data }` 或 `{ error }` 结构，客户端只把请求地址改为主站接口。

解析所需 AI SDK 作为主站运行时依赖安装；模型选择和提示词保持 `ik` 原实现不变。服务端不得记录上传文件内容，文件只在单次请求内存中处理。

## 数据流

1. 用户在实验室下拉框选择“IK 冲击试验”并挂载模块。
2. 工作区先显示 `ik` 原有示例记录。
3. 用户选择 PDF，客户端执行原有类型和大小检查。
4. Express 接口解析并执行 Schema 与能量映射校验。
5. 客户端用返回数据更新原 IK 看板，并生成实验室标准摘要。
6. 实验室现有草稿、综合判定、归档和打印流程消费该摘要。

## 错误处理

- 非 PDF、空文件、超过 15 MB：保持原中文错误语义。
- Schema 或能量映射不一致：返回 422，并展示具体校验消息。
- AI 解析失败：返回原有通用重试提示，不暴露服务端内部错误。
- 草稿中的旧数据缺少 `IK_IMPACT` 时不受影响；恢复 IK 摘要时优先使用 `moduleData`，不可用则回退到示例数据和已保存摘要。

## 测试与验收

- 测试先证明实验室契约尚未注册 `IK_IMPACT`，再补最小实现。
- 覆盖 IK Schema、能量映射一致性和摘要映射。
- 覆盖服务端文件缺失、类型、大小及解析响应边界；AI 调用使用可替换的解析函数隔离外部服务。
- 验证下拉项、渲染分派、草稿/归档摘要和打印均识别 `IK_IMPACT`。
- 运行相关 Vitest、`pnpm run check` 和 `pnpm run build`。

验收完成的定义：实验室下拉框可选择并挂载“IK 冲击试验”，原模块 UI 可正常显示和上传解析，结果进入实验室综合摘要、草稿、归档和打印链，类型检查与生产构建通过。
