# 看板入口访问密码开关设计

## 目标

当前取消进入项目看板时的访问密码，同时完整保留访问密码、会话、限流和登录界面代码，便于后续重新启用。

本次只影响“查看看板前的访问密码”。管理员写入密码、API Key，以及新增、修改、删除等写操作的鉴权保持不变。

## 方案

新增服务器环境变量 `DASHBOARD_ACCESS_ENABLED` 作为入口访问密码的唯一开关：

- 未设置、设为 `0` 或设为 `false`：入口访问密码关闭，用户直接进入看板。
- 设为 `1` 或设为 `true`：入口访问密码开启，恢复现有登录流程。

默认关闭是本次发布所需状态。服务器现有的 `DASHBOARD_ACCESS_PASSWORD` 不删除、不改名，因此以后只需设置 `DASHBOARD_ACCESS_ENABLED=1` 并重启服务即可重新启用。

## 服务端行为

鉴权中间件先判断入口开关：

- 开关关闭：跳过入口访问会话校验并继续执行后续中间件。
- 开关开启：维持当前行为，公开健康检查与登录接口，其他看板请求必须持有有效访问会话或机器 API Key。

跳过入口鉴权不等于跳过写入鉴权。写请求仍继续经过现有 `apiKeyAuth`，必须持有管理员写入会话或有效 API Key。

访问会话状态接口增加 `required` 字段：

- 关闭时返回 `required: false`、`authenticated: true`。
- 开启时返回 `required: true`，并按现有 Cookie 判断 `authenticated`。

访问密码的登录、退出、Cookie 签名、过期时间和失败限流代码全部保留。开关关闭时登录接口不参与正常页面流程。

## 前端行为

`DashboardAccessGate` 读取状态接口的 `required` 字段：

- `required: false`：直接渲染看板，不显示登录页面或“安全退出”按钮。
- `required: true`：保持当前加载、登录、重试、定时校验、聚焦校验和退出流程。

如果状态接口无法访问，仍显示错误/重试状态，不使用浏览器本地存储作为降级来源。

## 配置与重新启用

当前发布不需要修改服务器 `.env`，因为开关默认关闭。

后续重新启用时，在服务器运行环境中设置：

```text
DASHBOARD_ACCESS_ENABLED=1
```

保留原有 `DASHBOARD_ACCESS_PASSWORD`，然后通过正式发布或受控重启流程使配置生效。

## 测试

自动化测试覆盖：

1. 开关默认关闭时，生产环境无访问 Cookie 也能读取看板 API。
2. 开关关闭时，访问会话状态报告 `required: false` 和 `authenticated: true`。
3. 开关开启时，无访问 Cookie 仍返回 `DASHBOARD_ACCESS_REQUIRED`。
4. 开关开启时，正确密码仍能创建 HttpOnly 访问会话。
5. 开关关闭不改变管理员写入鉴权，未授权写请求仍被拒绝。
6. 前端在 `required: false` 时直接显示看板且不显示退出按钮，在 `required: true` 时保留登录流程。

发布前继续执行类型检查、相关 Vitest 测试、生产构建、OSS 门禁和标准发布守卫。

## 非目标

- 不删除登录界面或访问密码相关服务端代码。
- 不取消管理员写入密码。
- 不改变 API Key、Cookie 有效期或登录限流规则。
- 不新增本地存储或其他客户端鉴权兜底。
